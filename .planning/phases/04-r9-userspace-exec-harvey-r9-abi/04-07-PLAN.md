    1. trap.S entry: replace the `=interruptstackbase`+INTERRUPTSTACKSZ stack switch with a
       load of the current process's kstack top — `ldr x0, =CURKSTACK; ldr x0, [x0]; mov sp,
       x0`. CURKSTACK is a kernel .data symbol initialized to interruptstackbase +
       INTERRUPTSTACKSZ so pre-process traps (early boot, virtpanic) behave exactly as today.
       After the frame is built (post `sub sp, sp, #288` + stores), record it: `ldr x9,
       =CURFRAME; mov x10, sp; str x10, [x9]` (x9/x10 are frame-restored later from their
       slots — safe scratch). In the restore tail (trap_return), RELOAD the frame base instead
       of assuming sp is unchanged: `ldr x9, =CURFRAME; ldr sp, [x9]` as the tail's first
       instruction — preemption swaps CURFRAME/CURKSTACK/TTBR0 mid-trap, and the tail then
       pops the NEW current proc's frame. Rust side: `#[unsafe(no_mangle)] static CURKSTACK:
       u64` / `CURFRAME: u64` in proc.rs, written only under the PROC_TABLE lock or in
       IRQ-masked trap context (single CPU; document the invariant).
    2. proc.rs scheduler: `reschedule()` — round-robin scan of PROC_TABLE for the next Ready
       proc after current; if none or current is still Running-and-only: return None. On a
       switch: stash the live frame pointer (CURFRAME value) into current.frame, mark current
       Ready, set current = next, write CURKSTACK = next.kstack_top, CURFRAME = next.frame,
       `vm::switch(next.root_table, RootPageTableType::User)` (the 04-05-ungated call), print
       the preemption evidence marker `sched: switch {old_pid}->{new_pid}` (dev_exec only —
       marker-not-order discipline per D-13). `preempt()` = the timer-tick entry: call
       reschedule(); the trap tail's CURFRAME reload does the rest.
    3. proc.rs blocking support (for Task 2's AWAIT): `sched()` — swtch(&mut
       current.context, &sched_context) after marking current Blocked; the sched context is a
       per-boot context saved on first use whose loop picks Ready procs and swtch()es into
       their saved .context (or eret-returns to Ready-not-blocked procs via the CURFRAME
       path); waking sets Blocked → Ready. Ordering assignment (checker revision 1): when the
       sched loop picks a proc to resume, the SCHED LOOP ITSELF applies the same locked
       CURKSTACK + CURFRAME + TTBR0 swap (and current_proc update) as reschedule() — one
       PROC_TABLE-locked step, executed BEFORE swtch()es into that proc — so the resumed
       proc's trap-return tail reloads its own CURFRAME, never the previous proc's.
       EL0 entry/exit NEVER rides swtch — only
       kernel-context (blocked mid-syscall) switches do (the experiment's documented limit).
    4. timer.rs: under cfg(dev_exec) tick() calls `crate::proc::preempt()` (no printing — the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| EL0↔EL1 (preemption) | an IRQ mid-userland swaps address spaces and kernel stacks; a stale frame or wrong TTBR0 crosses process isolation |
| parent↔child (rfork copy) | the child's address space is a byte copy of the parent's — aliasing or shared pages break isolation |
| syscall context↔scheduler (blocking) | a process blocked in AWAIT trusts its kstack frame to survive other processes' traps |
