
## 07-04 session findings (lima guest toolchain)

- **02-4 root cause pinned:** vm-run.sh's ensure sentinel `GHB="$GUEST_DIR/.build/hostbin-linux-aarch64/bin"` is a RELATIVE path checked after `cd "$GUEST_DIR"` in the same remote shell, so the tested path is `harvey-build/harvey-build/...` — it never exists, and `nix run .#setup && nix run .#toolchain` re-runs on EVERY darwin-leg invocation (minutes per run).
- **Race hazard:** each vm-run.sh push rsyncs with `--delete`, wiping the guest's gitignored `sys/src/cmd/unix/9cc/obj.linux` (a darwin host has only obj.darwin); toolchain.sh lacks `set -e`, so a raced nm.BUILD failure (ar: lib9.a/libmach.a missing) doesn't stop the chain — a zombie build keeps mutating the shared guest while the next push wipes obj.linux under it. Observed twice in this session; converges once the guest is quiet. Fix candidates: absolute GHB, `--exclude 'obj.*'` (or ctimes-based skip) on the push, `set -e` in toolchain.sh.

## 07-07 session findings (r9 kernel)

- **The exit-sweep deferral has a measured wall:** PROC_TABLE slots are never reaped this era (a Moribund husk pins its slot), so MAX_PROCS is a boot-session FORK BUDGET, not a concurrency bound. The net sweep hit it at 16 slots mid-loop ("proc: table full" at arp-send 3; the sweep forks ~20 times). 07-07 bumped the table to 64 (3× gate headroom). The real fix is reaping: a Moribund slot's husk serves nothing once its wait record is consumed (the /proc listing already filters Moribund; pids are never reused) — the design constraint is the ProcGuard raw-pointer discipline ("slots never freed/moved"), which a reaping path must retire or re-prove. Any long-lived shell/service era (Phase 8's ip stack + auth) will fill 64 too.
- **slirp ARP replies arrive at 64 bytes, not 60** (the guest's requests are 60 — our ETHERMINTU write path): slirp pads its replies past the Ethernet minimum (measured on qemu 11.1.2's libslirp; the 07-05 assertion suite's synthetic fixtures pinned 60 and 07-07 relaxed the reply check to ≥60/runt-fails). If Phase 8's ethermedium parses slirp frames by length-class, take the measured shape from the committed pcap (evidence/07-07-virtnet-arp.pcap).
