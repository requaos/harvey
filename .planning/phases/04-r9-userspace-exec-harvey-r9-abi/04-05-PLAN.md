## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| EL0→EL1 syscall arguments | every syscall arg (fds, buffer pointers, path strings, argv arrays) is user-controlled data crossing into kernel reads/writes |
| syscall context↔IRQ context | the devcons write path holds the Console MCS lock while the timer IRQ fires |
| exec image swap | freeing the current image while running on it is a use-after-free class of bug |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-11 | Elevation of Privilege | syscall.rs arg handling | critical | mitigate | proc.validate_user_range checks every user-VA argument (buffer, path, argv pointer + each pointed-to string) against the calling proc's segment map BEFORE any kernel read/write; invalid → errstr + -1, never a kernel dereference. (Canon user-boundary discipline — breadcrumb: also covered by /gsd-secure-phase's V5 review at phase audit) |
| T-04-12 | DoS | devcons write vs timer IRQ (Console MCS lock) | high | mitigate | Pitfall-3 fix: the tick's println is cfg(not(dev_exec))-compiled out of exec profiles, so no IRQ-context code ever takes the Console lock once syscalls can print; the PL011 RX path stays lock-free raw-DR |
| T-04-13 | Tampering / DoS | exec.rs image replacement | high | mitigate | Parse-and-validate the new a.out completely BEFORE freeing any current mapping; on any failure the old image is intact and EXEC returns -1/errstr (donor semantics); the frame rewrite happens only after a fully seeded new image |
