<objective>
Build the D-06/D-07 execution harness: the pinned 9front donor tree builds its own CONF=qemu arm64 reference kernel in the lima Linux namespace using Harvey's vendored 7a/7c/7l, and the result boots to an rc shell under qemu TCG on the host with captured serial proof. This harness is the TC-03 execution gate (plan 02-05) and the TC-05 acceptance gate (plan 02-07).

Purpose: without a running reference kernel, "the toolchain works" is unprovable (Phase 1's boot-test lesson: build-green masked LP64 miscompilation; only execution exposed it).
Output: three committed harness scripts + the gitignored donor checkout and kernel artifacts + a captured boot-to-shell log.

**Flagged assumptions (spec-less probe fallback — surfaced not dropped):**
- A4 (research): the donor-tree build inside a lima Linux namespace with our hostbin on PATH is fully specified but not prototyped — this plan IS the prototype. If the in-donor-tree build proves intractable after honest effort (document the attempts in the SUMMARY), D-07 requires surfacing a checkpoint:decision for the pinned-prebuilt fallback — never a silent downgrade of the proof standard.
- A5 (research): 9front's CONF=qemu kernel boots under qemu -M virt TCG as shipped (it is 9front's own tested target); a drift failure here is donor territory, not our toolchain.
- A2 (research): a pinned prebuilt 9front arm64 image is obtainable — fallback only.
- Guest-state partitioning (wave-2 parallelism, declared): this plan's driver rsyncs the Harvey checkout to guest dir harvey-build-donor and the donor tree to guest dir 9front-donor; wave-2 peer 02-03's pre-gate build owns vm-run.sh's default guest dir harvey-build and mutates it with guest-only scratch injection. No mutable guest path is shared between the two same-wave plans, so parallel wave execution is race-free without a declared ordering edge. The one-time cost is a second guest toolchain build in harvey-build-donor.
- The donor build's host-side helper tools (mkpaqfs, aout2uimage, and any generator the donor mkfiles invoke) must be compiled from donor sources for the linux guest with plan9port 9c; the exact set is discovered from the donor mkfiles at execution time (their names are load-bearing and listed in the donor's arm64/mkfile).
- Dropped prohibition candidates (breadcrumbs, canon/routine): no minimega for aarch64 (x86/KVM-only upstream — carried-forward decision); no kernel-source edits in the donor tree (vendor fidelity — if the donor kernel fails to build from pristine sources, that is A4/A5 escalation, not a patch invitation).
</objective>
