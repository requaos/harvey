<objective>
The measure-first gate for the whole kernel stream: trace the REAL boot chain (our Phase-2/05-02
aarch64 binaries — boot, init, paqfs, rc, and the sweep commands) on the 9front donor kernel via
the Phase-2/Phase-4 harness, and produce the measured syscall-set artifact every dispatch-growth
plan implements from.

Purpose: the carried-forward policy is "implement exactly the measured set; loud-unimplemented
stays." Without this artifact, 05-04+ would implement from source-reading alone — A1's list is
informed but unmeasured. This plan makes the set authoritative.
Output: 05-03-trace.txt + the trace-rig extension.

Method note (the pid-1 problem): boot(8) syscalls from its first instruction, so the 04-01
launch-then-arm pattern can miss its earliest calls. The rig therefore (a) traces init, rc, paqfs,
and the sweep binaries fully (launch backgrounded → stop → startsyscall loop, the proven 04-01
shape), and (b) for boot itself either arms instantly via an rc one-liner or records the slippage
— any boot-flow syscalls not captured are listed as source-verified additions (boot.c's opencons
closes/binds/opens are already read and named). The artifact header states which.
</objective>
