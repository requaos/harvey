<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fd table across fork/dup | shared kernel objects (pipe queues) are reachable from multiple processes — a wrong clone semantics corrupts another process's I/O |
| #s registry | an fd handed to devsrv outlives the registering process — the clone must keep the underlying object alive |
| EL0 → sys_pipe/sys_dup/sys_create args | untrusted pointers/integers on every call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10 | Tampering | fd/pipe fork-dup semantics | medium | mitigate | Arc-shared queue with clone-on-dup (never byte copies); host tests pin the fork matrix (default copy / RFFDG share / RFCFDG fresh); bounded queue with a named overflow errstr |
| T-05-11 | Elevation of Privilege | devsrv fd registration | low | mitigate | devsrv clones the registered chan at write time (the Arc keeps the queue alive after the registrant exits — matching devsrv.c's fd-holding semantics); listing exposes names only |
| T-05-12 | Tampering | sys_pipe/sys_dup/sys_create user args | medium | mitigate | T-04-11 validation-first handlers (sargs + validate_user_range before any read/write of the fd array or path); 32-bit masking of int-width args |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs this plan; the phase audit (05-RESEARCH.md Package Legitimacy Audit: none) is the verdict of record |
